# Omulimi Engineering Rules

1. Never destroy working functionality without a clear reason.
2. Inspect existing code before modifying it.
3. Do not blindly rewrite the application.
4. Never expose API keys, passwords, tokens, or secrets.
5. Never commit .env files or production credentials.
6. Frontend checks are NOT sufficient for security; enforce authorization on the backend/database.
7. Validate untrusted user input.
8. Follow the existing project architecture unless there is a strong technical reason to change it.
9. Test changes before declaring a task complete.
10. Keep changes focused and reversible.
11. Update TASKS.md after completing significant work.
12. Record important architectural decisions in DECISIONS.md.
13. New user-facing branding must use Omulimi, not Farvo.
14. Ask for approval before destructive database or production operations.
